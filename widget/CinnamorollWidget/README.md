# 시나모롤 Threads 콘텐츠 위젯

기존 Kuromi 위젯의 macOS 플로팅 패널 방식을 따라 만든 별도 앱이다. 작은 시나모롤 캐릭터를 눌러 패널을 열고, Threads의 새 글을 읽어 검수용 카드뉴스·릴스 초안을 만드는 기존 파이프라인과 연결한다.

## 실제로 연결되는 프로그램

위젯은 부모 프로젝트의 다음 스크립트를 실행한다.

```text
automation/meta-threads/run_daily.py
  ├─ fetch/fetch_posts.py      기존 AppMarketing 환경 파일의 THREADS_ACCESS_TOKEN 사용
  └─ transform/transform_posts.py
```

Threads 토큰은 위젯이나 새 설정 파일로 복사하지 않는다. 시작 시 `fetch_posts.py --check-only`로 토큰 설정의 존재만 로컬 확인한다. `새 글 불러오기`는 새 원글과 기존 글의 본인 후속 댓글을 조회한다. 작성자와 답글 연결 관계로 이어 쓴 본문만 합치며, 타인 댓글에 답한 별도 대화는 제외한다. 글 목록에는 `이어 쓴 댓글 N개 포함`이 표시되고, 선택한 글의 카드 생성은 병합된 전체 원문 계획으로 연결된다. 새 이미지 작업 직전에도 해당 글의 대화를 다시 확인한다. 이미 진행 중인 이미지 작업은 시작 당시 원문을 유지한다. 성공 결과는 기존 `automation/meta-threads/queue/`에 저장된다.

- 카드는 4–6장, 릴스 대본이 함께 생성된다.
- 자동 게시 기능은 없다.
- `새 글 불러오기`는 수집·초안 변환만 실행한다 (`--skip-cards --skip-render`). 새 조회가 카드 제작이나 예전 영상 재렌더를 함께 실행하지 않는다.
- 과거 전체 조회 완료 기록이 없으면 버튼은 `전체 글 불러오기`로 표시되며 `--backfill-history`를 함께 실행한다. API의 마지막 과거 페이지를 성공적으로 읽은 뒤에는 `새 글 불러오기`로 바뀌어 증분 조회만 한다. 중복 저장된 글은 다시 만들지 않는다.
- `ChatGPT로 카드·릴스`는 기존 로컬 카드 계획과 전체 원문으로 Safari 이미지 제작 흐름을 실행한다 (`--web-images`). OpenAI API를 사용하지 않으며 관계없는 영상 패키지를 함께 렌더하지 않는다. 제목이 알리는 번호 목록이 끊겼다면 기존 Threads 연결로 작성자 자신의 연결된 후속 글만 읽어 회수한다. 전체 원문·출처를 별도 보관하고 누락된 번호가 남으면 생성 전에 멈춘다. 긴 목록은 내용을 버리지 않고 최대 12장에 밀도별로 배분한다.
- 이미지 제작은 장별 생성 → 원본 다운로드·비율 확인 → 원문 대조 검수 → 오류 카드만 한 번의 보정 라운드 → 저장된 카드의 요소·배경 분리 → 효과음만 있는 9:16 릴스로 이어진다. 검수 판정은 숫자·단위·출처·원문 밖 주장·누락·한글을 포함하는 구조화된 응답으로 받는다. 불명확한 판정은 승인하지 않으며, 한 번 수정 후에도 오류가 있으면 이미지만 보관하고 릴스 제작은 멈춘다. 자동 검수가 사람의 최종 게시 검수를 대신하지 않는다.
- `production/card_motion/web_image_workflow.py`는 요청 식별자·대화·응답·원본 해시·검수·보정 횟수를 보관하고 `safari_images.py`는 전용 Safari 창의 ChatGPT 페이지만 제어한다. 다른 탭 추가, 주소 변경, 응답 식별 실패, 다운로드 모호함은 중단 조건이다. 스크린샷·썸네일을 원본 이미지 대신 저장하지 않는다.
- Safari의 `웹 개발자를 위한 기능 보기`와 `Apple Events의 JavaScript 허용`, macOS의 위젯→Safari 제어가 필요하다. 프로그램이 이 권한을 자동으로 켜지 않는다. 로그인·CAPTCHA·사용 한도·Safari 화면 변경도 실제 실행의 차단점일 수 있다. 앱 메뉴의 `Safari 연결 확인`은 프롬프트를 보내지 않고 연결만 검사한다 (`--web-images-check`).
- 중단된 이미지 작업은 `ChatGPT 제작 이어받기`로 표시된다. 전송 여부가 불명확하면 같은 요청을 다시 보내지 않는다. 렌더만 실패했으면 이미 저장·검수한 카드로 재시도한다. 실제 웹 이미지 생성→다운로드→영상 완주 검증 여부는 별도 실행 보고서를 확인한다.
- 이전 문안 JSON 복사 작업이 남아 있을 때만 `ChatGPT 답변 이어받기`로 기존 `--only-cards` 흐름을 유지한다. 기존 대기 답변·승인 카드·완성 영상은 새 웹 이미지 작업으로 덮어쓰지 않는다.
- 이어받기 기록은 누락 답변이나 카드 제작 실패가 있으면 유지한다. 검증한 문안은 보관해 로컬 제작 실패 때 다시 복사하지 않아도 재시도하며, 이미 완료한 글은 중복 제작하지 않는다. 위젯은 답변 대기·답변 누락·로컬 제작 실패를 구분해 표시한다.
- `카드 이미지로 릴스 만들기`는 4~12장 PNG/JPEG/WebP를 파일명 순서로 가져와 요소·배경 분리부터 모션·효과음·세로 MP4까지 처리한다 (`--from-images`).
- `보관 글`은 Threads 큐의 `source.json`에서 글 ID를 중복 제거한 누적 보관 수다. Threads 전체 게시물 수를 뜻하지 않는다. 최근 조회의 신규 수는 상태 줄에 `새로 추가 N개`로 따로 표시한다.
- 위젯과 Python 제작기는 프로젝트 루트의 `project-paths.json`을 함께 읽는다. Threads 큐와 `content/card-news/`, `content/reels/제작 자료/`의 `renders/latest.json`을 읽어 보관 글 수와 검수 준비 영상 수를 보여준다. `릴스 폴더`는 날짜·원문 제목으로 정리한 `content/reels/완성 영상/`, `카드뉴스 모음`은 `content/card-news/generated/`을 연다. 이전 숨김 경로는 호환용이며 중복 집계하지 않는다. `awaiting_audio` 상태는 검수 영상에 포함하지 않고 음원 선택 대기 수로 따로 알린다.
- `카드 분석·영상 만들기`는 가장 최근 승인 카드를 선택해 레이아웃을 분석하고 요소별 HyperFrames 영상을 만든다. Threads 토큰·새 글 수집·웹 ChatGPT를 열지 않으며, 같은 입력의 완성 영상은 재사용한다. 자동 분석 패키지는 검수 필요 상태를 유지하고, 수동 요소 계획은 덮어쓰지 않는다.
- 위젯의 `localRenderCheck`은 디스크의 매니페스트와 현재 MP4/검수 이미지 경로만 확인한다. 인코더 실행 성공, 영상 내용, 외부 서비스 상태를 보증하는 검증은 아니다.
- `최근 완성 영상`은 입력 해시가 일치하는 정상 영상만 표시한다. 별도 미완성 패키지가 있다고 정상 완성 영상의 열기를 막지 않는다.
- `영상 열기`는 최종 MP4를, `검수 이미지`는 인코딩된 영상에서 뽑은 장면 이미지를 연다. 둘 다 `ready_for_review` 상태이고 실제 파일이 있는 경우에만 활성화된다.
- 펼친 패널에는 제목·계정명·중복 캐릭터 헤더를 표시하지 않는다. 접힌 캐릭터는 패널을 여는 버튼으로 유지한다.
- Python은 `/opt/homebrew/bin/python3`, `/usr/local/bin/python3` 중 설치된 런타임을 명시적으로 실행한다. macOS 기본 Python이나 임의 PATH 파일에 의존하지 않는다.

## 프로젝트 접근과 진단

- UI의 `저장 파일 접근 필요` / `접근 허용`은 이 프로그램의 카드·영상 저장 위치를 읽고 저장하기 위한 macOS 권한을 뜻한다
- 최초 실행 시 `접근 허용`에서 **바이브코딩 릴스 폴더만** 선택한다. 앱이 카드·영상 저장 위치를 먼저 열어준다. 상위 Documents/Project 폴더나 다른 프로젝트를 선택하면 저장하지 않는다
- 시스템 파일 선택창으로 승인한 프로젝트만 북마크로 연결하며, 실행 시 이 연결을 복원한다. 전체 디스크 접근이나 다른 계정 권한을 요청하지 않는다
- 승인 전에는 보호된 프로젝트를 자동으로 읽지 않는다. 수량은 `—`로 표시하고 제작 버튼은 비활성화한다
- 실패 원문은 `~/Library/Logs/CinnamorollContentWidget/latest-run.log`에 토큰·인증 쿼리를 숨겨 저장한다. 파일 권한은 600이며 `기록`/앱 메뉴에서 열 수 있다
- 코드 서명을 변경하는 재빌드 후에는 macOS가 접근 재확인을 요구할 수 있다. 조회 성공을 앱 실행 성공으로 대신 판단하지 않는다
- 현재 로컬 빌드는 ad-hoc 서명이다. 재빌드하면 앱 해시가 달라져 Safari 자동화 허용이 켜져 있어도 기존 허용 기록이 새 앱과 맞지 않을 수 있다. 프로젝트 접근·새 영상 표시 성공을 Safari 연결 성공으로 대신 판단하지 않는다. 앱별 허용 기록 초기화는 사용자 승인 후에만 수행하며 다른 앱 권한은 초기화하지 않는다

## 빌드 및 실행

프로젝트의 일반 `python3`, `swiftc`, `codesign`이 필요하다. Python Pillow는 Dock 아이콘을 패키징할 때 사용한다.
캐릭터 크기와 외곽선을 맞추는 `Sources/UnifiedMascotStyle.swift`도 이 위젯 폴더에 함께 들어 있어, 다른 프로젝트 파일에 의존하지 않고 빌드된다.

```bash
cd "/Users/kimmac/Documents/Project/돈 자동화/바이브코딩 릴스/widget/CinnamorollWidget"
./build.sh
open "dist/시나모롤 콘텐츠 위젯.app"
```

기본 빌드는 같은 경로에 있는 앱을 덮어쓰지 않는다. 다시 빌드할 때 기존 결과를 의도적으로 교체하려면 `./build.sh --replace`를 사용한다. 앱은 `dist/`에서 바로 실행 가능하며, 별도로 `~/Applications`에 설치하지 않았다.

## 앱 안에서 확인할 수 있는 것

- `Threads 설정 있음 · 수동 조회`: 비밀 토큰 값을 노출하지 않고 기존 설정 파일에 값이 있는지만 확인한 상태. 유효성·만료 여부는 실제 조회 시 판별된다.
- `전체 글 불러오기 / 새 글 불러오기`: Meta Threads API 페이지들을 조회한 다음 새로 보관한 글의 초안을 만든다. 과거 조회가 완료된 뒤에는 새 글만 확인한다.
- `ChatGPT로 카드·릴스 / 제작 이어받기`: 웹 이미지 생성·검수·저장·릴스를 연결한다. 실제 생성 단계가 미완료이면 완료로 표시하지 않는다.
- 앱 메뉴 `Safari 연결 확인`: Safari 연결 검사만 한다. 이미지를 생성하거나 다운로드하지 않는다.
- `최근 카드 다시 만들기`: 가장 최근 승인 카드 한 패키지만 9:16 모션 영상으로 렌더한다.
- `최근 완성 영상 / 영상 열기 / 검수 이미지`: 정상 검수 MP4와 장면 이미지를 연다.
- `초안 폴더`: 기존 큐 폴더를 연다.

## 캐릭터 아트
