# 카드 이미지 → 릴스 제작기

사용자가 승인한 4:5 카드 이미지로 9:16 릴스를 만든다. 기본 카드뉴스는 4~6장,
기존 사용자 카드 시리즈는 최대 12장까지 가져온다. 글자와 그림을 다시 생성하지
않는다. PNG 입력은 자동 분리·연출하며 기존 검수 연출은 보존한다.

## 카드 PNG만 넣어서 만들기

위젯의 **카드 이미지로 릴스 만들기**에서 번호 순서의 이미지 4~12장을 선택한다.
Threads·ChatGPT·OpenAI API를 호출하지 않고 다음 작업을 프로그램이 처리한다.

`원본 복사 → 로컬 OCR/그림 경계 분석 → 원본 픽셀 RGBA 분리 → 별도 배경 복원
→ 원본과 재합성 비교 → 역할별 모션/읽기 시간/효과음 결정 → HyperFrames MP4 → 검수`

같은 작업의 명령행 엔트리:

```bash
/opt/homebrew/bin/python3 automation/meta-threads/run_daily.py \
  --from-images 카드1.png 카드2.png 카드3.png 카드4.png --title "카드 제목"
```

좌표·42개 요소·36.6초 설정을 입력하거나 기존 패키지에서 복사할 필요가 없다.
`content/reels/제작 자료/cards-import-<날짜>-<고유값>/`에 원본, 분리 PNG, 배경,
해시가 연결된 메타데이터, 자동 연출 설정, 검수 이미지, MP4를 저장한다.
기존 카드·영상은 덮어쓰지 않고 자동 게시하지 않는다.

현재 평면 추출은 밝은 일러스트/정보 카드 전용이다. 사진·복잡한 전체 배경은
분리 실패를 보고하며 완성으로 처리하지 않는다. 가려진 그림을 복원했다고
주장하지 않는다. OCR은 좌표·읽기량에만 쓰고 글/숫자를 다시 쓰지 않는다.
캐릭터의 눈·옷·팔 같은 연결된 부분은 하나의 강체 레이어로 묶는다.

## 누끼·모션 검수 기준

누끼는 축소본에서 찾은 영역을 그대로 확대하지 않고 원본 해상도의 선과 면으로 다시 맞춘다
흰색뿐 아니라 크림·연한 초록·연보라 패널의 원본 면도 포함해 내부가 빠지는 것을 막는다
OCR 글자와 해당 말풍선·패널은 원본 픽셀을 나눠 한 래퍼 안에서 같이 움직인다
글자 밑을 임의의 평균색으로 덧칠하지 않는다
같이 움직일 RGBA 조각은 원본 해상도로 먼저 합성한 뒤 브라우저에서 한 번만 축소해 머리카락·글자 경계 틈을 막는다
서로 가린 캐릭터·말풍선은 공유된 원본 선을 확인해 하나의 모션 그룹으로 유지한다
한 원본 윤곽이나 흰 내부가 분리 과정에서 여러 조각에 배정됐으면 같은 그룹으로 다시 묶는다
카드 경계에서 잘린 캐릭터는 원본 캔버스 경계에서만 윤곽을 닫아 보이는 내부를 보존한다
PNG에 없는 가려진 얼굴·몸을 새로 만들어 복원했다고 표시하지 않는다

`motion_effects.py`·`motion_effects.js`가 역할·위치·페이지에 따라 효과를 결정한다
현재 지원: 기존 페이드·슬라이드·팝·와이프와 상하 와이프, 아이리스 공개,
스프링 정착, 바운스 정착, 곡선 진입, 작은 기울기, 단계별 픽셀 공개
캐릭터에 비균등 스케일·고무 변형을 적용하지 않으며 읽기 홀드에는 원래 위치·크기로 정착한다
자동 카드에는 계속 움직이는 전체 화면 카메라 드리프트를 넣지 않는다

문자 해독·실제 타자·숫자 롤링·텍스트 모프는 래스터 글자를 재작성할 수 있어 자동 선택하지 않는다
단계별 픽셀 공개는 문자별 타이핑이나 글자별 분리와 다른 효과다
입력 카드마다 원문을 보존한 채 지원되는 효과를 선택하며 50개 효과를 전부 구현한 것은 아니다

렌더마다 `renders/cutout-review-<해시>/`에 실제 투명 누끼를 체크무늬 위에 올린 검수판을 만든다
요소가 많으면 검수판을 나눠 저장하며 작은 글자·장식을 생략하지 않는다
원본 재합성 오차와 불투명 픽셀 변조도 확인한다
정지 재합성이 정확해도 의미 있는 누끼 분리까지 보장되는 것은 아니므로 이 검수판과 등장 프레임을 함께 본다
이 새 경로의 최종 품질은 출력 검수를 거친다.

PNG 자동 경로의 등장 배경은 전체 화면의 밝은 필드를 재생성한다. 구멍 난
원본 배경판을 노출하지 않는다. 원래 보였던 구름·그림자 등의 배경 픽셀은
전경 요소가 안착한 뒤 별도 레이어로 복원한다. 마지막에 전체 카드로 덮어
분리 결함을 숨기지 않으며, 재합성은 배경과 실제 분리 레이어만으로 검사한다.
검수 시트는 장마다 0.10/0.50/1.10초와 읽기 구간을 모두 보여준다.

## 프로그램 흐름

`automation/meta-threads/run_daily.py`가 Threads의 새 글을 가져와 `card-plan.json`, `card-copy.md`, `image-prompts.md`, `reel-script.md`, `reel-production.draft.json`을 검수 대기 폴더에 만든다. 전체 원문을 순서대로 배분하고 원문에 없는 사실을 만들지 않는다.

이미지 제작 단계는 **웹 ChatGPT**를 사용한다. `open_chatgpt.py`가 카드 계획에서 4~6장짜리 시리즈 프롬프트와 장별 후속 프롬프트를 `chatgpt-web/<입력 해시>/`에 만들고, 첫 프롬프트를 클립보드에 복사한 뒤 `https://chatgpt.com/`을 기본 브라우저에서 연다. API 키·OpenAI 이미지 API·별도 API 과금은 사용하지 않는다. 웹에서 생성된 이미지는 한글·수치·출처·디자인을 검수한 뒤 `assets/cards/`에 보관한다. 이미지 패널·도식의 모션 좌표와 소리를 `reel-production.json`에 확정하면 일일 실행이 MP4를 만든다.

검수된 패키지에만 `"reviewed": true`를 둔다. 프로그램은 각 본문 카드에 요소별 모션, 카드 4:5 비율, 오디오 결정, 마지막 프레임의 원본 복원 여부를 검사한다. 완성본과 인코딩된 영상에서 뽑은 장별 연락 시트·모션 전후 시트는 `renders/reel-<입력 해시>.mp4`, `renders/proof-encoded-<입력 해시>.png`, `renders/motion-proof-encoded-<입력 해시>.png`로 보관한다. 같은 입력으로 다시 실행하면 기존 출력물을 사용하고, 이미지·음악·설정이 달라지면 새 버전을 만든다. `renders/latest.json`이 현재 검수 대상이다.

자동 게시는 하지 않는다.

## Safari에서 생성·검수·저장까지 이어가기

위젯의 **ChatGPT로 카드·릴스**는 웹을 여는 기존 복사 전용 경로와 별개다.
`run_daily.py --web-images`가 전용 Safari 창에서 다음 흐름을 실행한다.

`전체 원문 확인 → 원본 디자인·캐릭터 참고 업로드 → 장별 이미지 생성
→ ChatGPT 원문 대조 검수 → 실제 원본 다운로드 → 필요한 카드만 한 번 보정
→ 승인된 카드의 자동 요소 분리·효과음·9:16 릴스 → 출력 검증`

제목에 50개처럼 번호 목록의 개수가 있지만 본문이 중간에 끊겼으면 기존
Threads 연결의 읽기 권한으로 작성자 자신의 명시적으로 연결된 후속 글만
회수한다. 다른 사람의 댓글이나 연결 근거가 없는 글을 원문에 섞지 않는다.
원본 계획을 덮지 않고 전체 원문과 각 글의 출처를 별도 보관하며, 누락 번호가
남으면 생성 전에 멈춘다. 긴 원문은 최대 12장으로 밀도별 배분한다.

`chatgpt-web-images/<작업 식별자>/job.json`과 `safari.json`이 요청·대화·검수·
다운로드 해시·보정 횟수를 기록한다. **ChatGPT 제작 이어받기**는 이 기록으로
중단 지점부터 재개한다. 이미 전송한 요청은 중복 전송하지 않고, 응답 위치나
다운로드가 모호하면 실패로 남긴다. 썸네일이나 스크린샷을 원본 대신 저장하지
않는다. 검수의 `unknown`은 통과가 아니며 한 번 보정한 결과에도 문제가 남으면
자동 릴스 제작을 진행하지 않는다. OpenAI API와 자동 게시를 사용하지 않는다.

Safari의 Apple Events JavaScript 허용 및 macOS의 위젯→Safari 제어 권한이
필요하다. 프로그램이 보안 설정을 자동 변경하지 않는다. 앱 메뉴 **Safari 연결
확인**은 새 요청을 보내지 않고 연결만 검사한다. 실제 생성·검수·다운로드의
성공 여부는 별도 작업 기록으로 확인한다.

## 자동 읽기 시간

자동 읽기 시간은 `auto_content_reading_after_settle_v2` 정책으로 계산한다
공백 제외 OCR/원본 레이어 글자 수 중 큰 값을 쓰고, 마지막 요소가 정착한 뒤
8.5자/초의 보수적 설계값으로 읽기 시간을 주며 마지막에 1.8초를 더 유지한다
14초 상한은 없다 제목만 있는 표지는 2초가 기본이며 말풍선·본문이 있는 첫 장은 글자 수가 적어도 본문 규칙을 따른다
원문을 줄여 짧게 만들지 않으므로 긴 글은 영상도 길어진다 수동 검수 타이밍은 보존한다
계산 근거는 각 카드의 `motion_timing`에 저장한다

## 완료된 웹 카드의 원본 캐릭터 복구

캐릭터가 다른 모양으로 생성됐으면 기존 완성 작업을 보존한 채 해당 장만
별도 수정 작업으로 준비할 수 있다

```bash
/opt/homebrew/bin/python3 production/card_motion/brand_repair.py \
  --base-job 경로/chatgpt-web-images/작업ID/job.json --card 2
```

위젯의 **ChatGPT 제작 이어받기**가 이 작업을 실행한다 기존 장들은 해시로
확인해 재사용하며 선택된 장의 캐릭터 없는 배경만 Safari ChatGPT로 생성한다
프로그램이 실제 투명 PNG 원본 두 개를 비율 유지해서 합성하며 캐릭터를 새로 그리지 않는다
예약된 아래 영역에 글·검은 선이 남아 있으면 덮지 않고 중단한다 합성된 PNG를
웹에 다시 첨부해 원문을 대조한 뒤 새 패키지에서 요소별 영상으로 만든다
원문·기존 작업·컷아웃 해시가 바뀌면 이어받기를 거부한다 별도 수정 작업에서도
원문 검수 실패에 따른 웹 보정은 한 번만 허용하며 이어받기로 횟수를 초기화하지 않는다
복구 기록에는 컷아웃 SHA, 투명 여백 경계, 합성 좌표, 비율 유지 방식이 남는다

기존 누끼의 흰옷 안쪽에 투명 구멍이 있으면 원본 그림의 흰옷 픽셀로만 복구한다
얼굴·머리를 포함하는 위쪽 84%의 RGBA 픽셀은 변경 전후 일치를 검사한다
이미 생성한 배경에서 합성만 갱신하려면 같은 명령에 `--refresh-cutouts`를 추가한다
이 작업은 생성·검수 기록이 있는 결과에만 허용하며 새 합성 PNG를 다시 검수한다
새 출력 폴더를 사용하므로 기존 카드·영상은 덮어쓰지 않는다

이미 복구한 작업을 다시 `--base-job`으로 지정해 표지처럼 다른 장을 고칠 수 있다
그때 이전 작업에서 재사용한 카드까지 원문·검수·PNG 해시와 명시적 원본 작업 연결을
따라 확인한다 큐 밖의 파일이나 바뀐 이전 작업은 받아들이지 않는다 선택하지 않은
장은 이미 복구된 캐릭터를 포함해 그대로 유지한다

## 카드별 릴스 배경

9:16 배경은 각 카드의 분리된 `background.png`에서 만든다 분리 파일이 없는
수동 카드만 해당 카드의 clean plate를 사용하며 원본 합성 이미지의 사람·패널·글자를
배경 재료로 쓰지 않는다 카드별 배경판과 위아래 확장 영역을 함께 생성하고
장면마다 제목 표시·진행 표시 색도 그 배경에서 추출한다 첫 장의 배경이나
고정 보라·라임 껍데기를 모든 카드에 공유하지 않는다
`generated.json`의 `page_backgrounds`에는 카드 SHA, 사용한 배경 SHA, 추출 테마와
배경 생성 정책이 남는다 배경·레이어·렌더 코드가 바뀌면 영상 캐시 해시도 달라진다
완료 작업을 다시 실행해도 검수 입력 해시가 같고 렌더 정책만 달라졌으면 카드 생성과
웹 검수를 반복하지 않고 영상만 새 해시로 출력한다 기존 영상은 보존한다 검수된
카드·배경·레이어 파일 자체가 바뀌면 자동으로 승인하지 않고 중단한다

## 자동 카드와 수동 검수 카드의 구분

HTML·만화 카드 제작기는 카드 PNG와 함께 `<카드명>.layers.json`, 실제 배경,
글자·캐릭터·말풍선·소품의 투명 RGBA PNG를 저장한다. 레이어를 원래 순서로
합쳐 카드 원본과 일치하는지 확인한 뒤 `reel-production.json`으로 전달한다.
자동 계획기는 이 원본 레이어와 본문 읽기량으로 요소·등장 시점·길이를
정한다. 이미지·레이어·분석 코드가 바뀌면 재계산하며,
42개 요소나 36.6초 같은 특정 패키지의 값을 새 카드에 복사하지 않는다.
원본 PNG와 원문은 바꾸지 않으며, 효과음만 쓴다.
`motion_review_required: true`는 분석 결과를 영상 검수 대상으로 남긴다는 뜻이고,
`reviewed` 값을 분석 과정에서 몰래 바꾸지 않는다.

사람이 검수해 작성한 요소 계획은 자동 계획기가 덮어쓰지 않는다. 기존 수동 패키지와
BGM/무음 결정도 보존한다. 특정 자동 패키지만 네트워크 호출 없이 분석·렌더하려면 다음처럼
실행한다.

```bash
/opt/homebrew/bin/python3 automation/meta-threads/run_daily.py --only-render \
  --manifest 경로/reel-production.json
```

배경·레이어·카드 SHA, 좌표, 투명도, 겹침 순서, 모션 요소의 누락을 검사한다.
움직이지 않는 출처·페이지 번호도 원래 순서로 남기며 캐릭터나 글자를 다시 그리지 않는다.
제작기에서 레이어를 유실한 자동 패키지는 `needs_layer_repair`로 멈춘다.
사용자가 PNG를 직접 가져온 `flat_images` 패키지는 위의 로컬 자동 분리를 수행한다.
제목만 분리되거나 한 장이 정적으로 남은 결과를 완성 처리하지 않는다.
`renders/latest.json`에 복구 대상 장을 기록하고 예전 MP4를 최신 결과로 표시하지 않는다.
기존에 승인된 수동 분리 계획은 그대로 유지한다.

새 카드 입력은 기존 패키지를 덮지 않는 전용 폴더로 가져온다.

```bash
/opt/homebrew/bin/python3 production/card_motion/auto_plan.py \
  --import-images 카드1.png 카드2.png 카드3.png 카드4.png \
  --output "content/reels/제작 자료/새-패키지" --title "카드 제목"
```

자동 계획의 요소/시간을 사람이 바꾸면 자동 재분석이 그 변경을 덮지 않는다.
승인된 원본 이미지가 이후 바뀌면 렌더를 거부한다.

## 사용자가 만든 카드 → 요소별 편집 가능한 릴스

현재 사용자 카드에는 `version: 4`, `renderer: hyperframes_element_story`를 쓴다.
각 장의 `motion_elements`에 검수한 원본 픽셀 좌표 `box`, 누끼 방식 `mask`,
등장 시점 `delay_ms`를 지정한다(최대 24개/장). 프로그램이 원본 PNG에서
투명 요소 PNG와 별도 배경판을 만들고 HyperFrames 프로젝트의 개별 이미지
레이어로 배치한다. 요소는 임의의 장식 수로 고르지 않고 원문의 이해 순서에
맞춘다. 이 9장에서는 2장의 5단계, 6장의 1·10·20·30년 수치, 8장의
체크 항목 5개, 9장의 두 비교 수치와 그래프를 각각 빠짐없이 등장시킨다.
말풍선 글자와 나무·캐릭터처럼 누끼 경계가 깨지는 부분은 원본에 고정한다.
구름이나 그림이 뒤에 있는 패널은 배경판을 복원해 각 정보 패널이
순서대로 들어오게 한다.
카드는 세로로 늘리지 않고 원래 비율로 놓되, 원본 상하단의 라벤더색을
9:16 화면 끝까지 연장해 다른 색 띠가 생기지 않게 한다. 하단의 잘린
캐릭터 끝만 64px 이내에서 자연스럽게 배경으로 녹인다. 원본과 분리된
요소 및 세로 배경판은 `renders/hyperframes-element-story-<해시>/assets/`에 남는다.
마지막 요소가 자리를 잡은 뒤 카드 원본을 교차 등장시켜 읽기 구간의
글·수치는 원본 픽셀 그대로다. 아래 기존 수동 검수 9장 예제만 장별 3.2~4.5초,
전체 36.6초이며, 새 자동 패키지는 카드별 읽기량으로 별도 계산한다.
카드 자체에 제목과 설명이 있으므로 별도 화면 제목과 `한 줄 요약`은 렌더하지 않는다.

기존 `version: 3`, `renderer: native_card_story` 경로도 이전 작업을 위해
유지한다. 원본 9장은 사용자 카드의 특수 패키지이며, Threads 자동 카드뉴스의
기본 4~6장 규칙은 그대로다. 수동 카드의 요소 좌표는 이미지 확정 뒤 검수한다.
새 PNG 가져오기에는 수동 좌표가 필요하지 않지만 모든 종류의 사진/배경을
완벽히 자동 분리한다고 가정하지 않는다.

카드별 설정에는 4:5 이미지의 상대 경로와 검수한 `motion_elements`를 넣는다.
`hook`은 관리용으로 선택 입력할 수 있지만 영상에 중복 출력하지 않으며,
`takeaway`도 필요하지 않다. `audio_decision: sfx_only`만 허용한다. 같은 입력을
다시 실행하면 생성된 HyperFrames 프로젝트와 MP4를 재사용하며, 설정·원본·제작 코드가
바뀌면 새 해시 버전으로 만든다. 영상의 1080×1920·30fps·길이·오디오와
매 장의 시작·중간 프레임에 원본 누락/검은 여백이 없는지 검사한다.
`renders/latest.json`에 현재 결과가 기록되고 자동 게시하지 않는다.

이번 사용자 카드 9장을 프로그램으로 다시 렌더하는 명령:

```bash
/opt/homebrew/bin/python3 production/card_motion/build_ready.py \
  --manifest "content/reels/제작 자료/stock-basics-motion-2026-10-01/reel-production.json"
```

`run_daily.py --only-render`도 동일한 설정 파일을 발견하고 처리한다.

## 레거시 카드뉴스 릴스 기본 속도

이 규칙은 기존 `native_card_story` 및 HTML 카드 릴스에만 적용한다. 표지는 **2초**,
이후 장은 **각 1.5초**로 고정한다. 새 자동 요소 분석 카드에는 적용하지 않으며,
`auto_content_paced`가 카드별 읽기량과 분석 결과로 시간을 정한다. 이전에 승인된
`seconds_per_card` 방식의 패키지는 원래 길이를 보존한다. 사용자 카드의
`native_card_story`와 `native_element_story` 경로도 첫 장 2000ms,
나머지 1500ms를 검사한다. 현재 HyperFrames 사용자 카드 9장은 읽기 시간을
늘린 별도 승인 패키지로, 이 기본 속도 정책을 적용하지 않는다.

## 제작 설정

`reel-production.json`에는 카드별 PNG 경로, 원본 PNG 좌표 기준으로 잘라 움직일 요소 `tiles`, 배경색·강조색, 장당 시간과 오디오 선택을 적는다. 요소의 `crop`은 픽셀 사각형, `shapes`는 실제로 이동할 마스크 영역이다. `offset`·`start`·`duration`은 원본 패널의 등장만 조절한다. 완전히 자리를 잡았을 때 원본 카드 픽셀과 달라지면 렌더를 중단한다.

음악은 해당 글에 맞게 고른다. 다른 글에 Jev 카드·효과음·음악을 자동 복제하지 않는다. 초록색 이동 점처럼 내용을 설명하지 않는 장식도 공용 렌더러에 없다. 웹 ChatGPT에서 생성한 이미지의 한글과 레이아웃은 직접 검수하기 전까지 신뢰하지 않는다.
