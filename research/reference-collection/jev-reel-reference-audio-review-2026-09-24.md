## 반복된 형식과 적용 방향

- 훅에서 문제/결과를 곧바로 제시하고, 소개말을 길게 두지 않는다.
- 화면의 주인공은 실제 제품 페이지·작업 결과 또는 하나의 큰 흐름도다. 작은 둥근 카드 여섯 장을 나열하는 방식은 이번 표본의 핵심 문법이 아니다.
- 자막은 짧은 반응/설명 단위로 쪼개고, 해당 화면의 근거를 가리지 않는다.
- Jev 콘텐츠에는 `실패 상황 → 가능한 선택 → Jev의 구조화된 판단 → 연결 앱이 실행` 순서가 맞다. 실제 Jev 응답을 만들지 않았으므로 선택 결과값·확률은 꾸며 넣지 않고 `개념 예시`로 표시한다.
- 사용자의 사진은 말하는 영상이 없으므로 넣지 않는다. 사용자가 제공한 뿔 달린 뱀 캐릭터를 한 번의 브랜드 장면에 원본 그대로 사용한다.

## 소리·음성 점검

기존 v9의 입력 오디오는 19.63초 길이의 `mixkit-laptop-keyboard-typing-2531-preview.mp3` 하나다. 렌더러는 이것을 15.6초 전체에 깔았고, 음악이나 내레이션 트랙은 넣지 않았다. 따라서 v9의 핵심 문제는 “배경음이 조용했다”가 아니라 **타자 효과음 하나를 배경음악처럼 반복 재생한 설계**다. 새 시안에서는 이 파일을 사용하지 않는다.

레퍼런스 기록에서 확인된 오디오 표기는 Jev 게시물의 `matrix (bl studio loop) (sped up)`, POV 사례의 `EsDeeKid · 4 Raws`, 워크플로 게시물의 `Multi-Agent AI Workflow Automation`이다. 이들 영상은 화면 자막/제품 화면 중심이며 말하는 인물이 보이지 않는다. 다만 인앱 웹 미리보기의 음량 슬라이더가 0으로 열려 **실제 음원을 청취해 목소리 유무·음색·BPM까지 확인한 것은 아니다.** 이전 문서가 이를 분명히 하지 않은 점을 정정한다.

그러므로 새 시안은 음성 복제나 임의의 AI 나레이션을 추가하지 않고, **저작권 사용 조건을 확인한 단일 음악 트랙만** 깐다. 키보드·클릭·알림 효과음은 전부 제외한다. 이는 레퍼런스에서 목소리 톤을 확인했다는 주장이 아니라, 확인되지 않은 음성을 만들어 넣지 않기로 한 제작 판단이다.
