# 카드뉴스·릴스 레퍼런스 재분석

조사일: 2026-09-23 (KST)

## 먼저 결론

반응이 높은 레퍼런스는 공통적으로 **예쁜 분위기보다 확인할 결과를 먼저 보여준다.**

- 카드뉴스: 첫 장에서 구체적인 문제나 약속을 던지고, 2~3장에서 가장 저장할 만한 정보를 준다. 마지막에는 한 가지 행동만 요청한다.
- 릴스: 첫 프레임에 얼굴·로고·인트로를 오래 두지 않고, 문제 화면이나 완성 결과를 바로 보여준다. 이후 실제 화면 조작과 짧은 자막으로 주장을 증명한다.
- 좋아요만 보지 않는다. 카드뉴스는 저장·공유·스와이프 완주, 릴스는 평균 시청시간·완주·재시청이 더 중요한 진단 신호다.

## 카드뉴스 레퍼런스에서 가져올 것

### 1. 커버는 분위기가 아니라 약속

Sprout Social은 첫 슬라이드에 강한 시각 요소나 명확한 약속을 두고, 각 장마다 한 가지 역할만 주며, 마지막에 저장·공유·댓글 중 하나를 요청하라고 정리한다. [Sprout Social 카드뉴스 가이드](https://sproutsocial.com/insights/instagram-carousel/)

따라서 `Jev가 뭐예요?`보다 아래처럼 손실이나 궁금증을 먼저 보여주는 편이 낫다.

> 코딩 AI가 또 실패했다. 그런데 진짜 문제는 그 다음이었다.

### 2. 2~3번째 장에 가장 센 정보

많은 카드가 첫 장만 공들인 뒤 2번째 장에서 설명이 느슨해진다. 첫 장에서 열어 둔 질문에 2~3번째 장에서 바로 답을 주고, 나머지 장은 증거와 적용 예시로 써야 한다. 카드뉴스는 스와이프를 한 번 더 하게 만드는 흐름이 핵심이다. [Autoposting.ai 분석](https://autoposting.ai/blog/instagram-carousel-strategy)

### 3. 마지막 장은 요약 카드로 저장되게

마지막에 새로운 설명을 추가하기보다 한 장만 캡처해도 되는 요약·체크리스트를 둔다. CTA는 여러 개를 섞지 않고 `저장해두고 다음 오류 때 꺼내보기`처럼 하나만 둔다.

### Jev 카드뉴스에 적용할 구조 (5장)

1. **문제/오픈 루프** — `코딩 AI가 또 실패했다. 다음엔 뭘 하지?`
2. **네 가지 선택** — 재시도 / 다른 AI / 다른 툴 / 사람 확인
3. **정의** — `Jev는 코딩하지 않고 다음 행동을 고른다`
4. **흐름** — 상황 입력 → Jev 판단 → 프로그램 실행
5. **저장용 요약** — 작업 AI와 판단 AI 비교 + `다음 오류 때 참고하려면 저장`

카드에는 실사 얼굴을 넣지 않고 뿔 달린 뱀 캐릭터를 보조 기호로만 쓴다. 캐릭터가 설명을 대신하면 정보 카드가 굿즈 이미지처럼 보이므로, 화면·도식·문장이 주인공이어야 한다.

## 릴스 레퍼런스에서 가져올 것

### 1. 첫 0.5~1초에 문제 또는 결과

Meta가 Reels 인사이트에서 총 시청시간과 평균 시청시간을 제공하는 이유는 초반 이탈을 직접 확인하고 훅을 고치기 위해서다. [Meta의 Reels 업데이트](https://about.fb.com/news/2023/04/instagram-reels-trending-audio-and-gifts-updates/)

따라서 `안녕하세요, 오늘은 Jev를 소개할게요`와 로고 인트로는 제외한다. 첫 프레임은 실제 오류 UI와 다음 행동 질문으로 시작한다.

### 2. 얼굴은 리액션, 기능은 실제 화면

공개 반응이 높았던 표본들은 얼굴이 나오더라도 곧바로 만든 앱·변환 결과·저장소 화면을 보여줬다. 얼굴만 길게 보여주면 바이브코딩 콘텐츠의 증거가 사라진다.

우리 릴스에서는 사용자의 원본 사진을 1~2초 리액션 PIP로만 사용하고, 얼굴 변형·립싱크·미용 보정은 하지 않는다. 핵심은 오류 화면, 선택지, 판단 결과, 실행 로그다.

### 3. 자막은 음성을 복사하지 말고 판단 단위로

화면에는 긴 문장을 전부 깔지 않고, `재시도?`, `다른 툴?`, `Jev 판단`, `프로그램 실행`처럼 시청자가 지금 보고 있는 선택만 남긴다. 음성은 설명하고 자막은 구조를 표시한다.

### Jev 릴스에 적용할 구조 (약 25~30초)

| 구간 | 화면 | 목적 |
|---|---|---|
| 0~1초 | `BUILD FAILED`와 큰 질문 | 스크롤 중단 |
| 1~4초 | 선택지 4개가 빠르게 등장 | 문제를 자기 일처럼 만들기 |
| 4~7초 | 사용자의 짧은 원본 리액션 PIP | 사람의 반응을 빌리되 설명은 화면에 맡기기 |
| 7~15초 | 상황 입력 → Jev 판단 UI | Jev의 역할을 한 번에 이해시키기 |
| 15~22초 | 판단을 받은 프로그램이 다음 도구 실행 | 판단과 실행 분리 증명 |
| 22~27초 | 작업 AI / 판단 AI 비교 | 기억할 한 문장 만들기 |
| 27~30초 | 저장·공유 CTA + 출처 | 다음 행동 요청 |

실제 Jev API 응답을 확보하지 못한 구간에는 `예시 흐름`을 계속 표시한다. 실제 확률·성공률·가격을 화면에 꾸며 넣지 않는다.

## 이번에 기존 시안에서 바꿔야 할 것

- 카드: 분위기용 배경을 줄이고, 2장에 선택지·3장에 정의·4장에 흐름을 배치한다.
- 카드: 마지막 장에 저장 CTA를 추가한다.
- 릴스: 첫 장면에 로고나 설명을 두지 않고 오류 화면을 0초부터 노출한다.
- 릴스: 사진 리액션은 1~2초로 줄이고 기능 화면을 더 오래 보여준다.
- 릴스: 실제 API 응답처럼 보이는 가짜 결과는 `예시 흐름` 라벨로 분리한다.
- 둘 다: 제목·문장보다 화면에서 확인 가능한 행동을 우선한다.
