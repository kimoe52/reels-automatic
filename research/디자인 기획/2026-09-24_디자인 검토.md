# 릴스·카드뉴스 전체 방향 재점검

검토일: 2026-09-24. 상태: 제작 방향 제안. 사용자 확정 조건과 이번 제안을 구분한다.
이 문서의 Jev 기획은 **이번 한 편에만 해당**한다. 후속 콘텐츠는 주제와 원문에 맞춰 별도로 기획한다.
이번 작업은 기존 결과·규칙·레퍼 기록의 검토다. 새 영상 렌더, 유료 생성, 게시, 자동 변환기 변경은 하지 않았다.

## 1. 계정에 이어갈 편집 원칙과 이번 편의 콘셉트

계정 전체에 이어갈 것은 주제와 근거를 분명하게 보여주고, 짧고 자연스러운 한국어로 설명하며, 읽기 쉬운 글자 체계와 출처 표기를 유지하는 것이다. 실제 화면·사진·도식 중 무엇을 쓸지, 이야기 구조·영상 길이·음악·편집 속도는 원문과 주제에 맞춰 매번 새로 정한다. 특정 도구 소개 형식을 모든 콘텐츠에 복제하지 않는다.

**이번 Jev 편만** 공식 자료를 따라가며 활용 예시를 설명하는 화면 중심 소개로 제안한다. 시청자가 가져갈 것은 “이 도구를 어디에 붙이는지 알겠다”는 이해다. 실제 API 호출·실행 결과를 확보하지 않은 상태에서 사용 후기나 성공 데모로 포장하지 않는다.

카드뉴스는 같은 내용을 멈춰 읽고 저장하는 설명물이다. 릴스 프레임을 그대로 카드로 복제하지 않는다.
두 형식의 일관성은 배경색·사진의 반복보다 글투, 글자 위계, 강조 방식, 출처 표기로 만든다.

## 2. 무엇이 잘못됐나

- v7: 사용자가 전체 콘셉트의 개선은 인정했지만, 말하지 않는 인물 사진·손 사진·AI 느낌을 빼라고 했다. 그 조건부 평가를 전체 승인으로 해석하면 안 된다.
- v8: 사진을 빼고도 실제 제품 화면 대신 그린 에디터가 중심이었다. 제작자의 면책 문구까지 설명 자막에 들어가 시청자에게 필요한 정보가 밀렸다.
- v9: 실제 화면 중심이라는 요청이 글자 슬라이드로 바뀌었다. 긴 키보드 녹음을 배경 전체에 붙여 시각적 행동과 소리가 분리됐다. 소리만 끄는 것으로는 해결되지 않는다.
- 공통: 정보의 연결과 실제 화면 증거보다 색·소품·효과를 먼저 정했다. 해상도, 파일 생성, 오디오 수치 확인은 했어도 실제 속도에서 읽히는지와 듣기 좋은지는 별개였다.
- 다른 유튜브 작업의 설정이 실제로 섞였다는 근거는 확인하지 않았다. 확인한 문제는 이 프로젝트 안의 오래된 ASMR·사진 PIP 기본값과 후속 수정의 불일치다.

## 4. 여러 주제에 이어갈 확정 조건

- 릴스에서 말하지 않는 인물의 사진 PIP, 손 사진은 사용하지 않는다. 이번 Jev 편은 화면만으로 설계한다.
- 실제 얼굴은 변형 금지, 카드뉴스 사용 금지. 이번 편에서 얼굴 사용 자체가 필요 없다.
- PIP는 필요할 때 활용할 수 있지만 의무가 아니다. 이번 편에서는 원본의 작은 부분을 확대하는 화면 PIP만 검토한다.
- 카드뉴스는 4~6장. 사람 캐릭터 또는 뿔 달린 뱀 캐릭터 중 하나만 사용해도 된다. 고정 좌우 배치·라벤더 배경·두 캐릭터 동시 사용은 요구 사항이 아니다.
- 지속 타자음으로 개발 분위기를 만드는 방식은 폐기한다. 예전 ASMR 선택을 이후의 명시적 거절보다 우선하지 않는다. 소리는 주제별로 정하되 타자음을 상시 기본값으로 쓰지 않는다.
- 원고와 결과 확인 외에 촬영·편집·툴 조작을 사용자에게 필수 작업으로 넘기지 않는다.

위 조건은 후속 콘텐츠에도 적용한다. **Jev에 관한 훅·사례·도식·화면 순서·22초 길이·음악 방향은 이번 편에 한정**하고, 계정 전체의 템플릿으로 취급하지 않는다.

## 5. 이번 Jev 편의 한 문장과 정확성

핵심: **작업이 막혔을 때, 재시도할지 다른 도구나 사람에게 넘길지 판단하는 단계를 내 프로그램에 붙이는 예시.**

이것은 활용 예시다. Codex의 기본 기능이거나 이미 작동 검증한 통합이라는 뜻이 아니다.
[Vercel 공식 설명](https://vercel.com/ai-gateway/models/jev)은 상태와 질문을 평가해 선택·점수·불리언 확률을 반환하는 모델이라고 설명한다. 실제 실행과 임계값·예외 처리는 이를 연결하는 프로그램의 몫이다. [TypeSafe 공식 설명](https://typesafe.ai/)도 소프트웨어 안에서 쓰는 판단과 신뢰도 중심이다.

피할 문구: “GPT는 판단을 못 한다”, “이것만 붙이면 자동 해결”, “반드시 더 싸고 정확하다”. 실측하지 않은 절감액·성공률·가짜 응답 확률도 금지한다.
공식 코드 예시가 환불 여부 확인이라면, 그것을 실패 후 도구 선택의 실측 코드처럼 보여주지 않는다.
가격·접근 조건은 영상 핵심에서 뺀다. 9월 24일 Vercel 페이지에는 9월 25일 종료 예정의 무료 프로모션이 있으므로 영구 무료나 초대만 가능하다는 문구를 고정하면 안 된다. 발행 시점에 다시 확인한다.

## 6. 이번 Jev 릴스 구조 제안 — 약 20~24초

22초는 읽기 시간을 위한 초안이지 유행의 정답이나 확정 길이가 아니다. 정보가 남으면 압축하고, 읽히지 않으면 시간을 늘린다. 14초 안에 다섯 설명을 밀어 넣지 않는다.

| 구간 | 실제로 보여줄 것 | 자막의 역할/초안 |
|---|---|---|

| 3~7초 | 같은 페이지의 평가·반환 형식 설명으로 시선 이동, 필요한 한 구절만 강조 | “그 판단 단계를 / 따로 붙이는 모델, Jev.” |

처음 던진 질문을 중간 도식이 풀고, 끝에서는 사용 방식까지 명확해져야 한다. 가격·기술 용어·신청 방법·모든 사용처를 한 편에 추가하지 않는다.

## 7. 이번 Jev 편의 화면과 편집

- 실제 페이지가 주 화면이다. 화면을 새 카드 안에 작게 넣거나 가짜 브라우저/터미널을 그리지 않는다.
- 원본 서비스 색을 살리고, 편집용 그래픽은 제한된 중립색과 강조색 하나만 쓴다. 배경 전체를 라벤더·크림색으로 통일할 필요가 없다.
- 인위적 느낌을 빼는 기준은 ‘AI 도구를 안 쓰기’가 아니라, 가짜 UI·근거 없는 반응·장식용 로봇/뇌 이미지·불필요한 네온/글로우를 빼는 것이다.
- 자막은 한 번에 한 의미, 최대 두 줄. 큰 한국어 글자가 화면의 핵심 UI를 가리지 않아야 한다. 화면이 밝고 복잡할 때만 얇은 반투명 바를 쓴다.
- 장면 전체를 계속 확대하지 않는다. 필요한 글자에 접근하고, 읽을 시간을 주고, 다음 근거로 넘어간다.
- 기본 전환은 컷. 새 정보가 나오는 순간을 먼저 정하고 박자는 보조로 맞춘다. 매 박자에 줌·전환을 넣지 않는다.
- 작은 코드가 전체 화면에 많이 나오는 것은 전문적으로 보이는 근거가 아니다. 필요하면 해당 몇 줄만 확대한다.
- 썸네일·큰 포스터가 매 장면 반복되거나 장면 번호·진행 바가 장식을 맡는 구성을 피한다.
- PIP를 쓴다면 ‘지금 보고 있는 화면의 세부 확대’ 같은 정보 기능이 있어야 한다. 이번 초안에는 인물·손·캐릭터 PIP가 없다.
- 실제 화면 확보가 막히면 미완료로 표시한다. 텍스트 카드나 생성형 개발 화면으로 몰래 대체하지 않는다.

## 8. 이번 Jev 편 사운드 제안

이번 편의 목표는 작업실 현장감이 아니라 **짧은 정보를 따라가게 하는 편집 리듬**이다. 여기 적은 음악 방향은 후속 주제의 기본값이 아니다.

- 이번 초안: 내레이션 없음, 음악 한 곡, 효과음 0개로 시작.
- 음악 후보 방향: 드럼과 짧은 베이스가 중심인 인스트루멘털 그루브. 약 100~115 BPM을 탐색 범위로 삼되, 숫자로 선정하지 않는다. 멜로디·고음·보컬이 한국어 자막보다 먼저 튀지 않고, 과격한 드롭이 없는 구간을 고른다.
- 첫 프레임부터 리듬이 있는 구간을 사용한다. 긴 인트로·반복 타자음·컵/종이/브러시 ASMR·알림음 묶음은 사용하지 않는다.
- 컷 일부를 악센트에 맞추되, 읽기 시간을 음악에 강제로 맞추지 않는다. 끝은 곡의 짧은 프레이즈 종료에 맞춰 정리한다.
- 목소리가 없으므로 음악을 무조건 거의 안 들리게 낮추지도 않는다. 파일의 LUFS/피크는 클리핑 확인용이고, 좋은 음색·피로도·적합성을 대신하지 못한다.
- 클릭을 추가하더라도 실제 클릭 동작을 이해시키는 경우만 별도 검토한다. 기본값으로 추가하지 않는다.
- 곡명과 최종 볼륨은 실제 청취 후 정한다. 현재 특정 곡을 적합하다고 확정한 상태가 아니다. 청취 수단이 없으면 검수 완료라고 하지 않는다.
- 레퍼 트랙은 출처·분위기 참고일 뿐 재사용 허가가 아니다. 게시 계정/배포처에 맞는 이용 권한을 확인한 곡만 최종 파일에 포함한다.

## 9. 카드뉴스 — 이번 Jev 주제 적용 예시

카드뉴스는 콘텐츠 주제에 맞게 4~6장으로 구성한다. 아래는 **이번 Jev 설명에 적용한 5장 예시**이고, 이후 주제에 고정 복제하지 않는다.

1. 표지: 다음 행동을 고르는 AI라는 한 가지 궁금증. 제품명과 간단한 분기 그림, 큰 제목으로 시선을 모은다.
2. 역할: Jev가 받는 것과 돌려주는 것을 짝지어 설명. 긴 소개 문단 대신 짧은 문장과 예시.
3. 활용: 릴스와 같은 실패 후 판단 사례. 상태·선택지·프로그램 실행 관계가 한눈에 읽히게 한다.
4. 경계: Codex 내부 설치가 아니라 API 연결이며 실행 주체는 프로그램. 자동 성공 도구로 오해하지 않게 한다.
5. 요약: 어떤 앱·자동화의 판단 단계에 쓸지와 공식 출처. 최신 가격/접근 정보는 꼭 필요하고 검증했을 때만 포함.

커버는 한 문장을 강하게, 본문은 설명 밀도를 높인다. 모든 장이 제목 하나와 큰 여백뿐인 포스터가 되어서는 안 된다.
글자 위계·정렬·여백·강조색을 통일하되 장마다 레이아웃 역할은 바꾼다. 캐릭터 하나를 안내나 반응에 쓰고, 실사 얼굴은 쓰지 않는다. 뿔 달린 뱀의 특징을 다른 생물로 바꾸지 않는다.

## 10. 다음 제작에서 통과해야 할 검수

1. 해당 주제에 필요한 원문·자료·근거를 먼저 확인한다. 실제 제품 시연을 주장할 때만 작동하는 실제 화면을 확보한다.
2. 그 주제에 적합한 도입 구간에서 화면·자막 읽기·소리의 조합을 시험한다. 전체 대본도 실제 속도로 읽어 분량을 확인한다.
3. 무음으로 보아도 문제와 Jev 역할이 이해되는지 확인한다. 이후 음원 후보를 청취하고 같은 구간에 맞춰 비교한다.
4. 완성본 전체를 실제 재생 속도로 검수한다. 프레임 모음 이미지나 ffprobe 수치만으로 영상 검수를 대체하지 않는다.
5. 원본 화면 진위, 자막 가림/안전 영역, 결론의 정확성, 음악의 시작/끝/피로도, 라이선스를 각각 확인한다. 수행하지 못한 검수는 미확인이라고 남긴다.

이번 검토에서는 파일을 덮어쓰거나 자동화 설정을 변경하지 않았다. 아래 문서는 과거 기획·자동화 기본값이므로 현재 조건에 맞춰 정리해야 한다. Jev 편 전용 구조를 새 주제에 기본값으로 옮기면 안 된다.
