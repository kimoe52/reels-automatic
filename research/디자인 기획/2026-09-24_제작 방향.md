# 이번 Jev 콘텐츠 제작 방향 — 상세 설명

**적용 범위:** 이 문서의 주제, 예시, 릴스 구성과 음악 제안은 Jev 콘텐츠 한 편에만 적용한다. 다음 콘텐츠는 다른 주제의 원문과 목적에 맞춰 콘셉트·장면·구조·길이·소리를 새로 잡는다. 계정의 일관성은 확인된 사실을 정확히 설명하고, 읽기 쉬운 디자인을 쓰는 정도로 유지한다. 이 문서를 다음 주제의 고정 템플릿으로 쓰지 않는다.

## 이번 Jev 편의 아이디어

이번 영상은 Jev API를 직접 써 본 후기나 작동 데모가 아니라, 공식 자료를 바탕으로 이 도구가 무엇을 평가하고 앱 안에서 어떻게 활용될 수 있는지 짧게 설명하는 소개다. 실제 호출 결과가 없으므로 성공 여부나 응답 확률을 만들어 보여주지 않는다.

보고 나서 시청자가 기억할 한 가지는 **“Jev에 판단을 맡길 수 있고, 그 결과로 실제 행동을 하는 건 내 프로그램”**이라는 점이다. 실패 뒤 재시도·다른 도구·사람 확인을 선택지로 드는 것은 하나의 활용 예시이며, Codex와 이미 연결된 기능이나 검증된 실사용 결과가 아니다.

## 화면 연출

이번 Jev 영상은 공식 웹페이지와 연결 문서를 큰 화면으로 보여주고, 설명이 어려운 부분에서 짧은 보조 도식을 한 번 쓴다. 화면을 가짜 브라우저나 가짜 코딩 에디터로 다시 만들지 않는다. 실제 화면의 어느 부분을 보고 있는지 잠깐 맥락을 보여준 뒤, 설명 중인 문장이나 코드 부분을 읽을 수 있게 확대한다.

자막은 화면의 문장을 그대로 반복하지 않는다. 화면은 근거를 보여주고, 자막은 그 뜻을 짧게 풀어준다. 한 장면에는 핵심 한 문장, 강조는 중요한 단어나 요소 하나만 둔다. 화면을 확대하는 동안 자막을 계속 바꾸지 말고, 읽을 시간을 준다.

이번 편에는 인물·손 사진을 장식으로 넣지 않는다. 사용자의 실제 얼굴 사진은 릴스에 쓸 수 있지만, 얼굴을 변형하지 않는 조건이 있고 이번 화면 설명에는 등장할 이유가 없다. 필요한 경우 PIP는 원본 화면 일부를 확대하는 용도로만 검토한다.

## Jev 릴스 구성 초안 — 약 22초

22초는 이번 설명을 위한 초안이다. 유행의 정답이나 다음 릴스에도 적용할 길이는 아니다. 실제 대본을 읽었을 때 자막이 급하면 늘리고, 내용이 이미 충분하면 줄인다.

| 구간 | 화면 | 자막 초안·역할 |
|---|---|---|
| 0~3초 | Jev 공식 페이지와 제품명이 보이는 화면 | “AI가 막히면 / 다음엔 뭘 시킬까?”로 궁금증을 연다. |
| 3~7초 | 공식 설명에서 평가·반환 형식에 해당하는 부분으로 이동 | “그 판단 단계를 / 따로 붙이는 모델, Jev.” 제품 소개와 역할을 연결한다. |
| 7~13초 | 원래 화면 위에 짧은 보조 도식: 상황 → Jev의 판단 → 내 프로그램 | “상황과 선택지를 보내면 / 다음 행동을 평가해 줌.” 재시도·다른 도구·사람 확인은 **활용 예시**라고 표시한다. |
| 13~18초 | 도식을 걷고 공식 연결 안내 화면으로 복귀 | “실제로 실행하는 건 / Jev가 아니라 내 프로그램.” SDK 예시는 실제 연결 안내로만 보여주고, 실행 결과인 것처럼 연출하지 않는다. |
| 18~22초 | 제품명과 출처가 보이는 화면 | “코덱스에 설치하는 게 아니라 / 내 프로그램에 API로 연결.” 핵심 사용 방식을 정리한다. |

가격과 신청 방법은 영상의 핵심에서 뺀다. 그런 정보가 콘텐츠 목적에 필요하면 게시 시점의 공식 안내를 다시 확인한 뒤 별도로 다룬다.

## 이번 편의 사운드 제안

지난 결과에서 타자음이 계속 들렸던 문제를 반영해, 이번 시안은 **내레이션 없음, 음악 한 곡, 효과음 0개**에서 시작한다. 음악은 실제 레퍼에서 들었다고 주장하는 것이 아니라 이번 편을 위한 제안이다.

후보는 보컬이 없고 드럼과 짧은 베이스 리듬이 있는 인스트루멘털이다. 첫 화면부터 리듬이 시작되는 구간을 고르고, 몇 군데 화면 전환만 음악의 악센트와 맞춘다. 자막을 읽을 시간을 음악 박자에 맞춰 줄이지 않는다. 긴 전주, 지속 타자음, 무관한 알림·클릭음은 이번 안에서 쓰지 않는다.

대략 100~115 BPM은 후보를 찾는 탐색 범위일 뿐, 선정 규칙은 아니다. 실제로 곡을 들어보고 화면과 자막을 가리지 않는지 판단해야 한다. 적절한 곡이나 최종 음량은 아직 확정하지 않았다. 볼륨 수치만으로 듣기 좋은지 판정하지 않는다.

## 카드뉴스는 릴스와 다른 역할

카드뉴스는 **4~6장**으로 구성한다. 이번 Jev 주제라면 5장이 한 예가 될 수 있다.

1. 표지: 다음 행동을 고르는 AI라는 궁금증을 연다.
2. 역할: Jev가 어떤 상태와 질문을 평가하는지 설명한다.
3. 활용 예시: 상황·선택지·프로그램의 관계를 보여준다.
4. 경계: 판단 결과와 실제 실행의 주체가 다르다는 점을 정리한다.
5. 요약과 공식 출처.

이는 Jev 카드뉴스의 예시 구성이다. 다른 주제에는 그대로 가져가지 않는다. 카드에는 실사 얼굴을 쓰지 않는다. 캐릭터는 사람 캐릭터나 뿔 달린 뱀 중 하나를 필요할 때 사용할 수 있고, 두 캐릭터를 모두 넣거나 라벤더색 배경을 고정할 필요는 없다.

## 다음 주제에서 이어갈 것과 다시 정할 것

다음 콘텐츠가 다른 주제라면, 원문에서 시청자에게 줄 가치를 먼저 정하고 그에 맞춰 연출을 다시 고른다. 화면 녹화가 적절한 주제도 있고, 사진·도식·현장 장면이 더 적합한 주제도 있다. 릴스의 길이와 이야기 순서, 목소리 유무, 음악 장르와 효과음도 매번 판단한다.

이어갈 수 있는 것은 명확한 근거, 짧고 자연스러운 한국어, 읽기 쉬운 글자 디자인, 사용자가 확정한 인물·이미지 조건이다. **“문제 질문 → 도구 설명 → 활용 도식 → API 연결”이라는 Jev 서사를 다른 주제에 반복하지 않는다.**

## 제작 후 확인

먼저 화면과 대본만으로 내용이 이해되는지 본다. 그다음 이 Jev 편에 맞는 음악 후보를 실제로 들어보고 붙인다. 최종본은 실제 재생 속도로 끝까지 보며 자막 가독성, 장면 전환, 음악의 시작과 끝을 각각 확인한다. 프레임 모음이나 음량 측정값만으로 완성도를 판단하지 않는다.
