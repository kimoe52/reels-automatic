# 릴스 변환기

Threads 원문을 `content/reels/제작 자료/릴스 구성 기준.md`를 참고해 릴스 대본·자막·제작 메모로 변환한다. 승인된 카드 PNG와 요소별 모션·소리 설정이 갖춰지면 공용 제작기가 검수용 MP4까지 출력한다. 원문과 첨부 캡처가 함께 있을 때는 먼저 게시글의 본문·프롬프트·미디어 설명을 읽는다. 첨부 이미지의 한 프레임을 디자인 레퍼런스로 오인해 복사하지 않는다.

## 제작 기준 적용

- 게시글에서 **제작 지시**와 **결과물의 한 장면**을 구분한다. 지시가 `공식 자료 조사 + 짧은 러닝타임 + 강한 시각적 전개 + 리듬감 있는 움직임`이라면 그 방법을 주제에 맞게 적용하고, 결과물의 수치·색·화면 구성은 근거 없이 베끼지 않는다.
- 실제 제품 설명은 공식 출처에서 확인한 내용으로 구성한다. 제품 UI가 꼭 필요할 때는 실제 화면을 캡처하고, 설명용 도식은 실제 UI인 것처럼 꾸미지 않는다.
- 계정의 릴스는 밝고 읽기 쉽게 만들되, 특정 파랑·연두 카드 레이아웃을 모든 주제에 반복하지 않는다. 원문이 설명형이면 원문 문장과 실제 근거의 시각적 위계를 먼저 설계한다.
- 생성 앱 UI는 기본 소재가 아니다. 원문에 사용 화면이 없는데 가상의 상태·횟수·응답을 만들지 않는다. 생성 소재가 꼭 필요하면 설명용임을 명시하고, 정확한 한글·가격·확률은 검증된 원문에서 별도 편집 레이어로 합성한다.
- 긴 정보글은 첫 문장만 반복하지 않고 역할 → 예시 → 연결 방식 → 다른 사용처 → 비용 조건 → 접근 방법처럼 원문의 주요 부분을 따라간다. 무음 시청에서도 읽을 수 있도록 러닝타임을 내용에 맞춘다.
- 제작 전 화면 문구를 원문 문장과 1:1로 대조한다. 원문에 없는 실패 횟수, 가격 계산 가정, 성공·선택 결과를 보태지 않는다. 공식 자료는 사실 확인과 출처 표시용이며, 사용자 글의 주제·서술 우선순위를 대체하지 않는다.
- 릴스 자막은 원문을 통째로 옮긴 긴 설명문이 아니다. 원문의 뜻을 유지하며 짧은 구어체·질문형으로 편집하고 `원문 → 화면 문구`를 기록한다. 한 컷에는 한 가지 생각만 두고, 실제 화면·도식·타이포그래피의 역할이 서로 다르게 보이도록 구성한다.
- 공식 사이트나 데모를 직접 캡처했다면 원본 URL과 캡처 날짜를 보존한다. 공개 데모가 게시글의 사례와 다르면 영상 안에서도 별도 사례임을 표시한다. 사이트 화면은 보여줄 지점만 확대·이동하고, 실제 실행을 증명하는 장면인 것처럼 과장하지 않는다.
- Threads 수집본이 연속 글의 첫 부분만 담을 때는 `transform/source-overrides/{post_id}.txt`에 사용자 제공 전체 글을 두고 변환한다. 원본 `source.json`도 보존해 두 출처를 구분한다.
- 배경은 주제에 맞는 단순한 바탕과 절제된 강조색으로 설계한다. 보라색 그라데이션·글로우·반복 그리드·떠다니는 카드 같은 일반적인 'AI 영상' 장식을 기본 템플릿으로 쓰지 않는다.
- Jev 응답이나 확률은 성공한 라이브 API 호출 결과에서만 가져온다. 호출이 없으면 임의의 결과를 넣지 않고, 문서 예시는 `공식 문서 예시`라고 명시한다.
- Jev 호출은 Jev를 다루는 현재 콘텐츠에만 한정한다. 다음 주제의 릴스 제작기에 Jev를 상시 연결하지 않는다. API 키는 채팅·저장소·렌더 로그에 기록하지 않는다.
- 렌더 전 타이포그래피·도형의 경계와 9:16 안전 영역을 검사하고, 인코딩한 결과의 필름스트립도 확인한다. 자막·도형·선이 화면 밖으로 나가거나 서로 겹치면 결과물을 전달하지 않는다.

이번 480p/업스케일 글의 현재 검수본은 `render_reference_edit_v6.py`로 출력한다. 사용자가 제공한 화면 녹화의 실제 화면·확대 컷·번호 챕터·짧은 하단 자막 전개를 세로 비율에 맞춰 적용한 전용 렌더러다. Higgsfield 공개 캡처는 시각 소재로만 사용하고, 본문에 없는 제품·요금 설명으로 확장하지 않는다. 다음 주제에는 이 사이트 화면과 480p 전용 문구를 자동으로 재사용하지 않는다.
